# Layout and structure benchmark

OCR character accuracy and document structure accuracy are separate problems.

The layout benchmark compares two Lao Document OCR AST JSON files:

- a reviewed reference AST
- a predicted AST generated by the pipeline being evaluated

This keeps layout metrics independent from CER/WER.

## Run

```bash
lao-ocr benchmark-layout \
  --reference reference.json \
  --prediction prediction.json \
  --output layout-report.json \
  --iou-threshold 0.5
```

Both inputs use the normal document AST schema emitted by the JSON exporter.

## Block matching

Blocks are matched per page by normalized bounding-box IoU.

Coordinates are normalized by page width/height before IoU is calculated, so a 600×800 reference page and a 1200×1600 prediction page can still match geometrically.

Matching is one-to-one and greedy by highest IoU above the configured threshold.

## Reported metrics

### Block precision / recall / F1

Measures whether expected semantic/layout blocks are detected without too many extras.

Matching is geometric and type-agnostic; semantic type is scored separately.

### Mean IoU

Mean normalized IoU of matched blocks.

### Block type accuracy

Among geometrically matched blocks, the proportion whose semantic type matches exactly:

- heading
- paragraph
- list
- table
- image

This avoids conflating “found the region” with “classified the region correctly.”

### Reading-order accuracy

For matched blocks, all ordered reference block pairs are checked.

A pair is correct when prediction order preserves the same relative order.

This is useful for multi-column documents where block detection may be correct but reading order is wrong.

### Table shape accuracy

For every reference table, checks whether the matched predicted table has the same row/column shape.

An unmatched or wrongly typed table counts as incorrect.

### Table cell precision / recall / F1

Cells are compared by structural identity:

```text
(row, column, row_span, column_span)
```

This directly measures:

- cell positions
- merged rows
- merged columns

Cell text is intentionally not part of the layout metric; OCR text quality remains CER/WER territory.

## Annotation guidance

Reference ASTs should be manually reviewed before they are treated as benchmark truth.

For each block, reviewers should verify:

- bounding box
- semantic type
- block order
- table row/column shape
- cell row/column position
- row/column spans
- image/header/footer roles where applicable

Do not modify reference annotations to make a specific model look better.

## Versioning

Once a public layout benchmark release is published:

- freeze reference ASTs for that release
- keep document/page IDs stable
- review annotation changes like source code
- report the exact benchmark commit/version with every result

## What this does not measure

This benchmark does not measure:

- OCR transcription accuracy
- visual typography fidelity
- exact Word spacing/margins
- font matching
- color fidelity
- pixel-perfect DOCX rendering

Those need separate CER/WER and DOCX-fidelity measurements.
